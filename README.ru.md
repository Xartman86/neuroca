## Как работает NeuroCA

NeuroCA заменяет матричные умножения **детерминированной битовой динамикой**, не
теряя способности решать алгоритмические задачи — на закрытом корпусе это держится
на уровне 479/660 EXEC по строгому протоколу (см. «Ключевые результаты»). Разберём,
из чего собрана машина, слой за слоем.

### Большая картина

```
                Python-код (exec-верификация)
                           ▲
        ┌──────────────────┴──────────────────┐
        │   Головка HybridPrefix (53M)         │  обучается, генерирует код
        │   d=256 · L=6 · H=8 · MoE 8 (top-3)  │
        └──────────────────┬──────────────────┘
                           │  ~530 признаков (FDIM=530)
        ┌──────────────────┴──────────────────┐
        │   Substrate3: бинарный КА            │  замороженный резервуар,
        │   9×9×9×8 = 5832 бита на торе        │  без градиентов
        └─────────────────────────────────────┘
```

### Нейрон = регистр на торе

Состояние нейрона — это **W-битный регистр** на **N-мерном торе**; вся сеть —
бинарный клеточный автомат в **N+1 измерениях**, где ось регистра играет роль
(N+1)-го измерения. Флагманская машина — 9×9×9×8 = **5832 бита**, ~130 млн
обновлений бит/с на CPU (без бит-упаковки).

### Субстрат: замороженный резервуар

Динамика КА даёт ~530 признаков (`Substrate3`), которые **никогда не обучаются** —
это фиксированный, воспроизводимый битовый резервуар (кэш признаков считается один
раз на корпус):

| Класс | Что отслеживает |
|---|---|
| Сдвиговые цепочки (12 токенов) | временные паттерны вдоль осей регистра |
| Синтаксические детекторы | структурные маркеры входных данных |
| Счётчики 8/16/32/64 | сколько раз повторился битовый паттерн |
| Фазовые часы | синхронизация битовых плоскостей |
| Конъюнкции + RBN | комбинаторная плотность / случайная булева динамика |

Это резервуарные вычисления в чистом виде: дёшево, детерминированно, богато.

### Головка: HybridPrefix

`HybridPrefix` — d=256, L=6, H=8, MoE 8 экспертов (top-3), FDIM=530, закрытый
словарь V=1078. Она читает признаки субстрата и генерирует Python-код. Ветка A —
53M параметров (с нуля); ранняя версия 7.2M оставлена для сравнения ёмкостей.

### Каскад: задача → анализ → стратегия → схема → код

Каждая задача проходит цепочку `задача → анализ → стратегия → схема → код`.
Внутренние стадии пишутся на **внутреннем иероглифическом языке** — компактных
радикалах вида `<SORT> <LIST> <RET>` (см.
[NeuroCA_internal_language.md](docs/NeuroCA_internal_language.md)): короткие
формальные планы, верифицируемые на каждом шаге.

![Каскад на внутреннем языке](assets/internal_lang_plan.png)

Пример — «найти максимум в списке»: анализ `LIST·SEARCH·NUM` → стратегия
`<LIST> <SEARCH> <RET> <CMP> <IF> <ACC> <ITER>` → схема
`best = xs[0]; for x in xs[1:]: if x > best: best = x` → Python, проверяется
exec-гейтом.

### Обучение: LLM-учитель + exec-верификация

NeuroCA учится не сама по себе — ей помогает **большая языковая модель-учитель**
(Ollama `qwen2.5:14b`, `qwen2.5-coder:14b`, `deepseek-coder`). Процесс простой:

1. учитель пишет решение задачи;
2. специальная программа **реально запускает** это решение (компиляция + тесты в
   песочнице);
3. в ученика (53M) попадают **только те решения, которые прошли проверку**.

Зачем так: маленькая модель перенимает умение большой, но без её ошибок — только
проверенные примеры. Измерено: из 208 решений учителя проверку прошли 106 (~51%).
Корпус — 33 семейства алгоритмических задач (сортировки, бинарный поиск, НОД,
сумма цифр, скобки, системы счисления, поиск максимума и др.), 1089 базовых строк;
в серии использовались также корпуса на 94K и 153K пар (сейчас — 279 042 пары).

### Верификация вместо совпадения строк

Обычно качество модели сравнивают с правильным ответом **по тексту**. Мы так не
делаем: код NeuroCA считается решённым, **только если он реально запускается и
даёт правильные ответы на тестах**. Дополнительно две страховки, чтобы цифры были
честными:

- **Проверка формата (формат-гвард):** каждый тест обязан пройти контроль формата.
  Именно так был пойман исторический баг в тестах, из-за которого метрика была
  завышена (82.4% вместо реальных 99.8% — в старом, более мягком протоколе);
- **Отдельный набор «краевых» входов (Тир1):** пустые списки, отрицательные
  числа, табы. Таких примеров нет в обучающем корпусе, поэтому модель не может
  их «выучить» — это честная проверка обобщения, а не памяти.

## Достижения (простыми словами)

Что NeuroCA умеет сегодня, без жаргона:

| Что умеет | Результат | Простыми словами |
|---|---|---|
| Решает алгоритмические задачи | **479 / 660** (строгий протокол) | пишет Python, который реально запускается и проходит тесты для 33 видов задач (сортировки, поиск, НОД, сумма цифр и др.) |
| Справляется с необычными входами | **358 / 620** (лучший в серии) | пустые списки, отрицательные числа, табы — того, чего не было при обучении |
| Учится без матричных умножений | КА-субстрат + головка 53M, ~130 млн бит/с на CPU | идея «без матриц» реально работает на этом масштабе |
| Учится у большой модели-учителя | 208 решений → 106 прошли (~51%) | перенимает умение, но не ошибки — только проверенные примеры |
| Думает по шагам | анализ → стратегия → схема → код | пишет короткие формальные планы на своём мини-языке перед кодом |
| Говорит честно | 36 версий, хэши чекпоинтов, отрицательные результаты публичны | каждая цифра привязана к чекпоинту; провалы публикуются |

И ещё одно, чтобы задать ожидания: NeuroCA — **не** попытка заменить чат-ботов.
Это исследовательская архитектура, отвечающая на один вопрос — можно ли заменить
матричные умножения детерминированной битовой динамикой и не потерять способность
решать алгоритмические задачи? На этом масштабе ответ *да*, и честная граница —
композиции (см. «Новости» ниже).

## Новости и находки (27–30.09.2026)

В одном месте, для читателя без контекста: что случилось **27.09** (почему цифры
оказались сложнее, чем казалось, — три корневых дефекта) и **30.09** (что умеет
модель сейчас — два новых замера).

### 27.09 — три корневых дефекта

1. **Дефект корпуса (корневая причина слабого Тир1).** При очистке текста
   программа молча удаляла слова, которых не было в словаре (OOV). Оказалось,
   что так исчезла **пятая часть обучающего текста — 21%** (23 097 из 107 541
   слова). После исправления (`NEUROCA_TOK_UNK=1` слова сохраняются как UNK)
   модель стала заметно лучше: эталон `unkbase` — **660=479, Тир1=355** (+45/+29
   к прежнему эталону). Это и есть главная причина, почему модель раньше
   спотыкалась на необычных входах.
2. **P2-формат-дефект: модель не видела формат тестов.** Бенчмарк проверяет
   модель на задачах вида «задача X: описание», но **ни один из 2094 учебных
   примеров не был записан в таком виде** — модель физически не могла этому
   научиться. Лечение (без использования тестовых задач): 264 описания
   переведены в нужный формат, добавлены 165 перефразировок учителя, учебник
   (29 задач), словарь расширен до 2451 слов. Корпус вырос до 279 042 пар.
3. **Вердикт G7 (эксперимент «выключи субстрат»).** На текущем масштабе (53M)
   признаки клеточного автомата **не дают заметного выигрыша** в точности
   (разница в пределах шума). Но обученная модель **без** субстрата почти
   перестаёт работать (4 из 660) — то есть субстрат важен как **опора**, а не
   как бесплатная прибавка. Честный отрицательный результат: на больших
   масштабах проверка ещё впереди.

Измеренные уроки серии: ёмкость решает «бинарность» профилей (7.2M→53M, overlap
признаков 0.764→0.285); рост качества — **от данных, а не от параметров**
(544→648→658 на старом протоколе); синтетические элизии/шаблонные шаги в корпусе
**вредят**; краевые данные сами по себе не вылечили Тир1; дефицит P2 имеет
**форматно-семантическую природу**, а не только словарную.

### 30.09 — что умеет модель сейчас

1. **Модель теперь думает по шагам (стадиальный каскад).** Вместо кода одним
   махом — сначала анализ, стратегия, схема, потом код. Результат: **469/660**
   на обычных задачах (уровень эталона) и **358/620 на «краевых» входах —
   лучший в серии**. Почему это важно: краевые входы (пустые списки,
   отрицательные числа, табы) не встречались при обучении, поэтому это признак
   настоящего понимания, а не запоминания.
2. **Композиции: знает кирпичики, но дом построить не может.** Проверили, умеет
   ли NeuroCA собирать проверенные примитивы в *новое* решение (например,
   «найти максимум» + «сравнить числа»). Правильно собрано только **3 из 860**.
   Любопытная деталь: модель в **96%** случаев верно угадывает аргументы, но не
   осваивает саму композицию. Почему это важно: это честная граница серии —
   учитель передаёт отдельные умения, но не «сборку».
3. **Почему мы это публикуем.** Отрицательные результаты — такая же часть науки,
   как победы. Баг данных 27.09 и граница композиций 30.09 не спрятаны — так и
   читателям, и нам понятнее, где проект находится на самом деле.

## Перспективы

Куда движется серия (измерено, а не обещано):

1. **Композиционное обобщение** — сборка проверенных примитивов в новые решения
   (сейчас 3/860): следующий шаг — данные композиций в корпусе.
2. **Стадиальный каскад как основной режим генерации** — он дал лучший Тир1
   (358/620) без потери качества на 660 (469/660).
3. **Масштаб** — начнёт ли субстрат КА окупаться за пределами 53M (на текущем
   масштабе он — опора, а не бесплатный выигрыш: G7).
4. **Внешние бенчмарки** — HumanEval (arXiv:2107.03374) запланирован как
   проверка вне корпуса.
5. **Тир2/Тир3** — переиспользование выученных примитивов, более глубокая
   проработка краевых входов.

## Исследования

Как получаются результаты и что держит их честными:

- **Версионированный реестр** — 36 версий экспериментов, каждая метрика привязана
  к чекпоинту/хэшу корпуса; эталон промотирован 27.09: `v120big50_unkbase`.
- **Строгий протокол** — eval с полным cue («задача X: <описание>»);
  историческая цифра 99.7% (голый cue) явно помечена как устаревшая.
- **Измеренные эффекты** — UNK-фикс +45/+29, перенос §14 +68…+108, ёмкость
  7.2M→53M (overlap признаков 0.764→0.285).
- **Абляции** — G7 (субстрат: опора, не бесплатный выигрыш; cross-ablation
  4/660); формат-гвард (пойман баг eval, завышавший 82.4%→99.8%).
- **Пост-эталонные замеры (29.09)** — стадиальный каскад `weak_ep6`
  (660=469 · Тир1=358/620) и композиции P2·G13 (3/860, arity-match 96.2%).
- **Контур учителя** — 208 генераций → 106 EXEC-валидных (~51% выход).

## Теории

Теоретические мосты, на которых стоит проект:

- **Клеточные автоматы и резервуарные вычисления** — детерминированная битовая
  динамика как замороженный резервуар (по духу ReLiCADA, RBN Кауффмана).
- **Нейронные КА / морфогенез** — Mordvintsev et al. (arXiv:2205.01681),
  Stovold (arXiv:2305.12971): линия роста/самоорганизации; наш субстрат намеренно
  заморожен — открытый вопрос, как внести адаптацию, не ломая детерминизм.
- **STaR-самообучение** (Zelikman et al., arXiv:2203.14465) — контур
  «учитель + exec-верификация».
- **Внутренний иероглифический язык** — короткие формальные планы между стадиями
  каскада; теоретические мосты: внутренняя речь Выготского, Бахтин, система 1/2
  Канемана, свободная энергия Фристона, L-системы (детали —
  [NeuroCA_internal_language.md](docs/NeuroCA_internal_language.md)).
- **Релевантные российские работы** — НКА для RL/самоорганизации и дистилляция
  знаний для LLM (линия Мокрецова/Татарниковой) — см. §2 статьи.
