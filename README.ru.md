## Как работает NeuroCA

NeuroCA заменяет матричные умножения **детерминированной битовой динамикой**, не
теряя способности решать алгоритмические задачи — на закрытом корпусе это держится
на уровне 479/660 EXEC по строгому протоколу (см. «Ключевые результаты»). Разберём,
из чего собрана машина, слой за слоем.

### Большая картина

```
                Python-код (exec-верификация)
                           ▲
        ┌──────────────────┴──────────────────┐
        │   Головка HybridPrefix (53M)         │  обучается, генерирует код
        │   d=256 · L=6 · H=8 · MoE 8 (top-3)  │
        └──────────────────┬──────────────────┘
                           │  ~530 признаков (FDIM=530)
        ┌──────────────────┴──────────────────┐
        │   Substrate3: бинарный КА            │  замороженный резервуар,
        │   9×9×9×8 = 5832 бита на торе        │  без градиентов
        └─────────────────────────────────────┘
```

### Нейрон = регистр на торе

Состояние нейрона — это **W-битный регистр** на **N-мерном торе**; вся сеть —
бинарный клеточный автомат в **N+1 измерениях**, где ось регистра играет роль
(N+1)-го измерения. Флагманская машина — 9×9×9×8 = **5832 бита**, ~130 млн
обновлений бит/с на CPU (без бит-упаковки).

### Субстрат: замороженный резервуар

Динамика КА даёт ~530 признаков (`Substrate3`), которые **никогда не обучаются** —
это фиксированный, воспроизводимый битовый резервуар (кэш признаков считается один
раз на корпус):

| Класс | Что отслеживает |
|---|---|
| Сдвиговые цепочки (12 токенов) | временные паттерны вдоль осей регистра |
| Синтаксические детекторы | структурные маркеры входных данных |
| Счётчики 8/16/32/64 | сколько раз повторился битовый паттерн |
| Фазовые часы | синхронизация битовых плоскостей |
| Конъюнкции + RBN | комбинаторная плотность / случайная булева динамика |

Это резервуарные вычисления в чистом виде: дёшево, детерминированно, богато.

### Головка: HybridPrefix

`HybridPrefix` — d=256, L=6, H=8, MoE 8 экспертов (top-3), FDIM=530, закрытый
словарь V=1078. Она читает признаки субстрата и генерирует Python-код. Ветка A —
53M параметров (с нуля); ранняя версия 7.2M оставлена для сравнения ёмкостей.

### Каскад: задача → анализ → стратегия → схема → код

Каждая задача проходит цепочку `задача → анализ → стратегия → схема → код`.
Внутренние стадии пишутся на **внутреннем иероглифическом языке** — компактных
радикалах вида `<SORT> <LIST> <RET>` (см.
[NeuroCA_internal_language.md](docs/NeuroCA_internal_language.md)): короткие
формальные планы, верифицируемые на каждом шаге.

![Каскад на внутреннем языке](assets/internal_lang_plan.png)

Пример — «найти максимум в списке»: анализ `LIST·SEARCH·NUM` → стратегия
`<LIST> <SEARCH> <RET> <CMP> <IF> <ACC> <ITER>` → схема
`best = xs[0]; for x in xs[1:]: if x > best: best = x` → Python, проверяется
exec-гейтом.

### Обучение: LLM-учитель + exec-верификация

STaR-подобный цикл: учитель (Ollama `qwen2.5:14b`, `qwen2.5-coder:14b`,
`deepseek-coder`) генерирует решения; **exec-харнесс** (компиляция + тесты в
песочнице) фильтрует их; в 53M-ученика дистиллируются только EXEC-валидные
решения. Измерено: 208 генераций → 106 EXEC-валидных (~51% выход). Корпус: 33
семейства алгоритмических задач (сортировки, бинарный поиск, НОД, сумма цифр,
скобки, системы счисления, поиск максимума и др.), 1089 базовых строк; серия также
обучалась на 94K и 153K пар (текущий корпус — 279 042 пары).

### Верификация вместо совпадения строк

Код оценивается **реальным исполнением**, а не похожестью текста, с двумя
страховками честных метрик: *формат-гвард* (каждый eval обязан пройти проверку
формата — так пойман исторический баг, раздувавший метрику с 82.4% до 99.8%) и
*набор краевых входов* (Тир1: пустые списки, отрицательные числа, табы),
отделённый от переформулировок.

## Ключевые результаты (серия v0.1–v120, 36 версий реестра)

| Показатель | Значение |
|---|---|
| EXEC-прогон 660 (33 задачи × 20), **эталон `v120big50_unkbase`** (промоция 27.09) | **479/660** (старые 345 / новые 134) |
| Тир1 (краевые входы, 620) | **355/620** |
| Прежний эталон `kit2b` (тот же строгий протокол) | 434/660 · Тир1 326 |
| Исторические 660 на старом протоколе (голый cue, `kit2b`) | 658/660 = 99.7% — см. примечание о протоколе |
| Производительность ядра | ~130 млн обновлений бит/с (CPU, без бит-упаковки) |
| Контур LLM-учителя (qwen2.5:14b) | 208 генераций → 106 EXEC-валидных (~51%); `second_max` 0→20/20 |

> **Примечание о протоколе (честность):** 99.7% измерено на старом протоколе
> (голый cue — только `«задача X»`). В сентябре 2026 eval усилен до **полного
> cue** (`«задача X: <описание>»`) — конструкции, которой, как выяснилось,
> **не было в обучающем корпусе** (см. P2-формат-дефект ниже). На строгом
> протоколе та же модель даёт 434/660; новый эталон `unkbase` — 479/660.

## Новые находки (27.09.2026) — корневые дефекты найдены

1. **Дефект корпуса (корневая причина Тир1):** `kit2_build.clean_text` молча
   выбрасывал OOV-слова — 23 097 из 107 541 слов (21%) не дошли до обучения.
   UNK-фикс (`NEUROCA_TOK_UNK=1`) восстановил их: `unkbase` **660=479, Тир1=355**
   (+45/+29 к `kit2b`) → новый эталон.
2. **P2-формат-дефект:** из 2094 обучающих cue **ровно 0** содержали
   конструкцию `«задача X: <описание>»`, которой тестирует P2 — модель никогда
   не видела этот формат; этим объясняется перевёрнутый разрыв «голый/полный cue»
   (373 vs 292). Лечение (без использования P2): 264 корпусных описания
   переведены в формат P2 + 165 перефразировок учителя + учебник (29 задач) +
   словарь V=2451 (покрытие P2-слов 80%). Корпус теперь 279 042 пары (+21.7%).
3. **Вердикт G7 (абляция субстрата закрыта):** 530 субстратных признаков **не
   окупаются** на 53M/104K — scratch 332±20 vs 366±24 (−34, незначимо); transfer
   434/326 vs 440/313 (шум). Однако модель, обученная **с** субстратом, без него
   отказывает (cross-ablation 4/660): субстрат — рабочая опора обученной модели,
   а не бесплатный выигрыш на этом масштабе.

Ключевые измеренные уроки серии: ёмкость решает «бинарность» профилей
(7.2M→53M, overlap признаков 0.764→0.285); рост качества — **от данных, а не от
параметров** (544→648→658 на старом протоколе); синтетические элизии/шаблонные
шаги в корпусе **вредят**; краевые данные сами по себе не вылечили Тир1;
дефицит P2 имеет **форматно-семантическую природу**, а не только словарную.

## Быстрый старт (ядро)

```bash
pip install numpy            # matplotlib нужен только для viz.py
python -c "
import sys; sys.path.insert(0, '.')
from neuroca.engine import RegisterCA
m = RegisterCA(shape=(9,9,9), W=8)   # машина 5832 бита
m.reset('random')
m.step(16)
print(m.bitplane_densities())
"
```

`eval_big50.py`, контур учителя) — часть лабораторной среды и доступен по
запросу; протокол честных метрик описан в статье (§4.3 формат-гвард, §6.4 аудит
Тир1).
